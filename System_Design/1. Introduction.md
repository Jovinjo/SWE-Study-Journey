# 1. Core Idea
No perfect design. A good design is where the choices match the problem!

- Pitifalls: "Use kafka, redis, cassandra"
- Best approach: "Start with requirements, build simple architecture, and solve problem"

# 2. What is system Design?

1. Requirements: What should the system do?
2. Scale: How many users, requests, writes, reads, and how much data should it handle?
3. Data: What data is stored, where is it stored, and how is it accessed?
4. APIs and communication: How do clients and services talk to each other?
5. Reliability: What happens when a server, database, network link, or external service fails?
6. Performance: What latency and throughput targets matter most?
7. Consistency: Which operations must be strongly correct, and where is eventual consistency acceptable?
8. Operations: How will the system be monitored, debugged, deployed, and evolved?
9. Cost: Is the design reasonable for the expected business and traffic scale?

# 4. How to approach a Design Problem
<img width="731" height="135" alt="image" src="https://github.com/user-attachments/assets/c624eb1d-aff4-406c-bd87-1fbf143456da" />

1. Clarify the requriements:
    - What are core features?
    - Who the users?
    - what should be excluded?
    - What operations need low latency?
    - what operations need strong correctness?
    - what durability expectations exists?
    
3. Estimate the scale: Estimate rough numbers for:
   - How many read and write requests per second
   - Storage growth
   - Bandwidth
   - Peak Traffic patterns
     
5. Start with simple small architecture (Only add components when there is clear reason and it evolve one contstraint at a time)
   - Client
   - API Layer
   - Application Service
   - Database
6. Identify Bottlenecks and Failure Cases:
   - What happens when database goes down or traffic increases?
   - What happens if cache empty or queue falls behind?
   - What happens when API third party becomes unavailable?
   - Which data must be taken into action/corrected immediately?

# 5. System Design in REAL LIFE
- System Design is about handling scale, latency, reliability, correctness, operations, cost!
- It is an ongoing process = Design > Measure > Learn > Revise
